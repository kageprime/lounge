# Real models (glTF / GLB)

Put `.glb` files in this folder and list them in `manifest.json`. Anything not listed keeps its procedural look.
The procedural prop shows instantly and is swapped for the model when it finishes loading; if a file is missing or
broken the procedural prop simply stays (check the browser console / `G.assets.failed`). `?models=0` turns all of it off.

## Where to get free ones (CC0)
- Kenney (kenney.nl/assets): Furniture Kit, and his other kits for plants, props and food. GLB included.
- Quaternius (quaternius.com): furniture and prop packs. Export as glTF/GLB.
- Poly Pizza (poly.pizza): searchable CC0/CC-BY low-poly models (check each licence).
File names differ between packs, so open the pack's folder and use whatever the files are called.

## Manifest entry
```json
"couch": { "files": ["sofa_a.glb", "sofa_b.glb"], "rotY": 180, "tint": [{ "material": "fabric" }] }
```
Key is a prop type (`couch`, `cabinet`, `stool`, `plant`, `table`, `pool`, `bar`, `claw`, `jukebox`, `vending`, `ludotable`),
or `type:id` (e.g. `"cabinet:cab0"`) for a single placed prop; the instance entry wins.

| field | meaning |
|---|---|
| `file` / `files` | one model, or several. With several, the number at the end of the prop id picks one (cab0, cab1, cab2... cycle), so neighbours differ |
| `rotY` | degrees to turn the model so its **front faces +z** (try 0, 90, 180, 270 if it looks backwards) |
| `scale` | fixed scale. Leave out to auto-fit (see below) |
| `height` | target height in room units (1 tile = 1). Still capped to the footprint unless `clamp:false` |
| `anchor` | `"back"` puts the model's back flush with the back of its tile (wall props: against the wall) instead of centring it. Use for deep models like cabinets |
| `offset` | `[x,y,z]` nudge after fitting |
| `tint` | `[{material, scale, emissive}]`: colour that material with the prop's `color` from layout.js |
| `emissive` | `{materialName: intensity}` makes a material glow (feeds the bloom) |
| `screen` | material name that should show the animated cabinet screen (cabinets / ludo table) |
| `spin` | node name to rotate (jukebox record) |
| `enabled` | `false` to switch an entry off without deleting it |

Auto-fit: with no `scale`/`height`, the model is scaled to fill its footprint (`w x d` tiles from `props.js`, 92%),
centred, and put on the floor, so models in centimetres, metres or "Blender units" all land at the right size.
Name materials in Blender (`body`, `screen`, `glass`...) so `tint`, `emissive` and `screen` can find them.
Materials are cloned per prop only when tinted, so 1000 identical props still share one material.

## Converting FBX (the arcade pack)
Three.js can load FBX but this pack's textures are separate PNGs that FBX does not link, so the cabinets are converted once, offline:
`python3 tools/fbx2glb_arcade.py /path/to/ArcadeAssets` writes the four skinned `cab_*.glb` (needs Python + numpy + Pillow).
It splits the screen into its own material (UVs remapped to 0..1) and bakes a glowing marquee emissive map.
The pack also has a Wide cabinet, a GunCade, a Driver (racing) cabinet and chairs/table/controls. Not used yet: Wide is 3 tiles wide and the
GunCade/Driver are deep, so they need a bigger footprint than the 1x1 cabinet tile.
`tools/scenesim.py` renders the whole layout from the manifest with flat colours, to catch scale / orientation mistakes without a browser.

## The included sample
`vending.glb` is generated by `node tools/make-vending-glb.mjs` (plain Node, no dependencies). It has vent slats and
panels on both sides, a tintable body and glowing product shelves. It exists to prove the pipeline and fix the blank sides;
swap it for a real model the same way.
